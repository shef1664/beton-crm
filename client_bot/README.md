# Клиентский AI-бот заказа бетона

> ⚠️ **УСТАРЕЛО / резервный вариант.** По решению проекта клиентский бот встроен в
> backend-процесс (`backend/bot/main.py`) и работает на существующем @otdprod_bot —
> отдельно запускать этот `client_bot/` НЕ нужно. Не запускайте его на том же токене
> одновременно с backend: два опроса на одном токене → конфликт Telegram (409).
> Этот каталог оставлен как автономный вариант (свой токен + отдельный worker-хостинг).


**Единственный клиентский бот** компании: вешается на **QR-код** / ссылку в рекламе.
Гибрид: **AI-продавец** свободно консультирует (какая марка под фундамент, объём по
размерам, цена), а оформление заказа идёт кнопками: марка → объём → адрес → стоимость
с доставкой → дата → оплата → телефон → заявка в CRM.

**Персональные данные (телефон, адрес) в нейросеть НЕ передаются** — их собирает
кнопочный поток и backend. AI (Claude) работает на стороне backend (`/api/ai/chat`),
провайдер переключаемый через `AI_PROVIDER` в `backend/.env`.

## Отдел продаж (группа + живой менеджер)

Задайте `SALES_CHAT_ID` (chat_id группы отдела продаж) и добавьте бота в эту группу:
- **Карточки заявок** — каждая заявка из бота падает в группу (имя, телефон, марка,
  объём, адрес, дата, оплата, сумма).
- **Живая передача менеджеру** — клиент нажимает «👤 Позвать менеджера» (или AI сам
  передаёт при недовольстве/спецвопросе). В группу приходит запрос; менеджер
  отвечает клиенту **через reply** на сообщение бота, «`/end`» завершает диалог.
  В режиме оператора сообщения клиента идут менеджеру, а не нейросети.

Как узнать chat_id группы: добавьте бота в группу и напишите там сообщение —
chat_id виден в логах бота (обычно отрицательное число).

Разделение ботов в проекте:
- **этот `client_bot/`** — для клиентов (заказ бетона с расчётом);
- **`@otdprod_bot` (`backend/bot/main.py`)** — только админ-панель + уведомления;
- **`bot/` (PULSAR)** — внутренний автопарк (роли водитель/слесарь/…), к заказам не относится.

## Как работает

```
Клиент (QR/ссылка) → /start
   → марка (кнопки М100…М450)
   → объём (м³)
   → адрес доставки (текст)
        → backend POST /api/quote
             (geo.py: адрес → км, бесплатный геокодинг Nominatim/DaData + OSRM)
             (calculator.py: цена бетона + доставки)
   → показ стоимости + возможности доставки
   → когда нужна доставка (Сегодня/Завтра/На неделе/Не срочно → влияет на приоритет в воронке)
   → способ оплаты (Наличные/Безнал/Перевод)
   → телефон (кнопка «отправить контакт»)
        → backend POST /webhooks/telegram
             → антидубль → автоматизация продаж → AmoCRM + SQLite + Telegram + Notion
```

Вся логика цены и расстояния — на backend. Бот только ведёт диалог.

## Запуск локально

```bash
cd client_bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # вписать CLIENT_BOT_TOKEN
python bot.py
```

## Деплой на Render

Отдельный worker-сервис:
- Build: `pip install -r client_bot/requirements.txt`
- Start: `cd client_bot && python bot.py`
- Env: `CLIENT_BOT_TOKEN`, `BACKEND_URL` (+ по желанию `DADATA_TOKEN`, `PLANT_LAT/LON`)

## Геокодинг (бесплатно)

По умолчанию — **Nominatim (OSM) + OSRM**, без ключей. Если задать `DADATA_TOKEN`
на backend — включится DaData (точнее по адресам РФ, 10k запросов/день бесплатно).
Настройки: см. `backend/services/geo.py` и `.env.example`.

## QR-код

Ссылка вида `https://t.me/ВАШ_БОТ` → сгенерировать QR любым генератором и
разместить на баннере/визитке/самосвале.
