# Аудит проекта: автоматизированный отдел продаж

Дата проверки: 2026-05-01

## Короткая оценка

Проект не пустой и не макетный. Это рабочий каркас системы продаж бетона:
лендинги принимают заявки, backend нормализует лиды, считает стоимость,
ведет локальное хранилище, готовит данные для amoCRM, Baserow, Telegram,
телефонии и голосового сценария.

Главный риск сейчас не в идее, а в доведении до стабильной эксплуатации:
секреты, окружение, деплой, чистка архивных PULSAR-файлов и реальные
интеграционные тесты с amoCRM/Telegram/Baserow.

## Что уже сделано

- FastAPI backend с health/status endpoint-ами.
- API создания и обновления лидов.
- Калькулятор стоимости бетона и доставки.
- Антидубли по телефону.
- SQLite-first хранение с опциональным зеркалированием в Baserow.
- amoCRM-интеграция для контактов, лидов, статусов и заметок.
- Telegram-уведомления и код Telegram-бота.
- Схема sales automation: приоритет, менеджер, playbook, SLA, следующий шаг.
- Workqueue для менеджеров: список, claim, отметка первого контакта.
- Универсальные webhooks для внешних источников.
- Отдельный telephony webhook.
- Голосовой sales-agent слой: старт звонка, обработка реплик, handoff.
- Главный лендинг и пять вариантов лендингов.
- Render-конфиг и Procfile для деплоя.
- Документация по CRM-схеме, быстрому запуску и границам проекта.

## Что исправлено в этой проверке

- Backend теперь импортируется на Python 3.9+ за счет отложенных аннотаций в
  модулях, где использовались типы вида `str | None`.
- Добавлен `backend/runtime.txt`, чтобы Render при `rootDir: backend` видел
  требуемую версию Python.
- Исправлен корневой `Procfile`: команда теперь заходит в `backend` перед
  запуском `uvicorn`.
- Команды открытия лендингов в `package.json` заменены с Windows `start` на
  macOS `open`.
- Добавлен `SQLITE_DB_PATH` в конфиг и `.env.example`, чтобы локальную SQLite
  базу можно было держать вне Google Drive или другой синхронизируемой папки.

## Что нужно доделать

1. Навести порядок в структуре:
   - оставить активные части `backend/`, `landing-main/`, `variants/`, `baserow/`;
   - перенести PULSAR-архив из `bot/`, `miniapp/` и части `docs/` в отдельную
     папку `archive/` или отдельный репозиторий.

2. Проверить секреты:
   - убедиться, что `backend/.env` не попадает в git;
   - заменить все реальные токены, если папка переносилась через облако;
   - держать секреты только в локальном `.env` и Render env vars.

3. Поднять локальный запуск на Mac:
   - установить Python 3.11;
   - создать venv;
   - заполнить `backend/.env`;
   - если проект остается в Google Drive, указать `SQLITE_DB_PATH=/private/tmp/sales-leads.db`
     или другой локальный путь.

4. Довести тесты:
   - добавить pytest smoke-tests без реальных внешних API;
   - мокировать amoCRM, Telegram и Baserow;
   - отдельно проверить сценарий создания лида и антидублей.

5. Доделать production-контур:
   - включить webhook secret для телефонии и внешних интеграций;
   - проверить Render persistent disk или внешний storage;
   - настроить CORS на реальные домены вместо `*`.

6. Доделать продукт:
   - добавить кабинет руководителя по лидам, SLA и источникам;
   - сделать интерфейс менеджера для workqueue;
   - добавить импорт лидов из CSV;
   - подключить реальные каналы: сайт, Telegram, телефония, Яндекс Карты, 2ГИС, Авито.
