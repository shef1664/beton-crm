# ТЗ для Кодекса: перенести бот счетов в этот репозиторий (для встройки в @otdprod_bot)

## Что хотим
Клиент в клиентском боте `@otdprod_bot` (уже встроен в backend) присылает **реквизиты
покупателя** — текстом, PDF или фото — и получает автоматически **счёт на оплату (PDF)**.
Сумма и позиции берутся из **текущего заказа в боте** (марка, объём, доставка, итог,
которые нейросеть уже собрала в диалоге). Продавец в счёте — ООО «ПУЛЬСАР»
(ИНН 4205271841, бренд «Бетон Экспресс»).

Бот счетов у нас УЖЕ разработан в Codex (папка «AI бухгалтерия»), но его кода нет в
этом репозитории `shef1664/beton-crm`. Из облака я его не вижу. Нужно перенести его
сюда, чтобы я встроил логику в существующего клиентского бота.

## Шаг 1. Задеплоить свежий backend (в нём уже есть фикс)
В master влит фикс: заявки из AI-диалога (Telegram и MAX) теряли марку/объём/адрес/сумму
— теперь параметры заказа и расчёт накапливаются в состоянии агента и гарантированно
попадают в карточку отдела продаж. **Задеплойте latest commit `beton-backend` на Render**
(как в `docs/CODEX_TASK_final_deploy.md`) и проверьте: новая заявка из MAX должна прийти
с маркой/объёмом/адресом/суммой, а не пустая.

## Шаг 2. Залить код бота счетов в этот репозиторий
Создайте в репозитории папку **`backend/services/invoice/`** и положите туда модуль
генерации счёта из «AI бухгалтерии». Ветку взять от master, запушить (PR или прямо в
ветку `claude/ai-accounting-folder-9ogq3f`, чтобы я подхватил).

Мне нужно, чтобы в папке было (адаптируйте имена под ваш код):
- **`generator.py`** — функция генерации счёта. Желаемая сигнатура:
  ```python
  def build_invoice_pdf(seller: dict, buyer: dict, positions: list[dict],
                        invoice_no: str | None = None) -> bytes:
      """Вернуть PDF счёта на оплату (bytes). positions: [{name, qty, unit, price, sum}]."""
  ```
  Если у вас другой интерфейс (файл на диск, reportlab/docx→pdf, готовый HTML→pdf) —
  оставьте как есть, но **опишите его в README рядом**, я оберну под бота.
- **`seller.json`** (или в коде) — реквизиты продавца ООО «ПУЛЬСАР» для шапки счёта:
  наименование, ИНН, **КПП, ОГРН, расчётный счёт, банк, БИК, корр. счёт**, адрес,
  подписант. Это не секрет (эти данные и так в счёте), но нужны для PDF. Если каких-то
  банковских реквизитов нет в коде — приложите их отдельным сообщением.
- **`parser.py`** (если есть) — распознавание реквизитов покупателя из текста/PDF/фото.
  Укажите, чем парсите:
  - текст — regex/эвристики по ИНН/КПП/р-с/банк;
  - PDF — извлечение текста (pdfplumber/pypdf) или OCR;
  - фото — OCR (tesseract) или **зрение Claude** (у нас уже есть `ANTHROPIC_API_KEY`,
    можно распознавать фото через vision — если так проще, скажите, я сделаю на нашем ключе).
- **`requirements.txt`** приложения счетов (reportlab, pdfplumber, pillow, и т.п.) —
  я сведу с `backend/requirements.txt`.

## Шаг 3. Что сделаю я после того, как код окажется в репо
Встрою в `backend/bot/main.py` (`@otdprod_bot`) сценарий «выставить счёт»:
1. После оформленной заявки / по кнопке «📄 Выставить счёт» бот просит реквизиты
   покупателя (текст / PDF / фото).
2. Приходит документ → `parser` достаёт реквизиты покупателя (PII парсится на нашем
   backend, в отдел продаж уходит как обычно; в нейросеть-консультант PII не отдаём).
3. `generator.build_invoice_pdf(seller, buyer, positions_from_order)` → PDF.
4. Бот отправляет клиенту PDF счёта; копия — в группу отдела продаж.
   Позиции/сумма — из заказа в боте (state: марка, объём, доставка, итог).
5. Аналогично подключу в MAX (`backend/bot_max/main.py`), когда Telegram-вариант заработает.
